Your job is to implement ONE development phase at a time from the project's LMS implementation plan.

First inspect the repository thoroughly.

Do not assume the project is empty.

Determine:
- Existing architecture
- Existing features
- Existing database models
- Existing APIs
- Existing frontend components
- Existing authentication
- Existing tests
- Existing conventions

1. Preserve existing functionality.
2. Do not rewrite unrelated code.
3. Follow existing architecture.
4. Use production-quality code.
5. Implement backend, database, API, and frontend portions required by the feature.

7. Validate all user input.
8. Handle errors properly.
9. Avoid hard-coded production data.
10. Avoid unnecessary dependencies.
11. Add database migrations.
12. Add tests.
13. Run formatting/linting/build/tests.
14. Fix errors caused by your changes.
15. Do not leave knowingly broken code.
16. Do not use mock functionality where real functionality is required.
17. Clearly identify anything blocked by missing infrastructure.
18. Document important architectural decisions.

At the end, provide:

- What you inspected
- What you implemented
- Files changed
- Database changes
- API endpoints added/changed
- UI changes
- Tests added
- Commands executed
- Test/build results
- Known limitations
- Recommended next phase
